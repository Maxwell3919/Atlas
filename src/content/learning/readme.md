这个 README 一直拖着没写。起初觉得，既然是个教学网站，把计算过程写清楚就好了，不太想往里面放自己的想法。最近一边做 DFT，一边用 AI 查资料、改输入、整理结果，还是想把我对学计算和用 Agent 的一些想法留在这里。

做 DFT 时，我首先得知道自己要算什么。研究的是哪个体系，关心哪个物理量，这个量需要经过哪些计算才能得到，拿到结果后又该怎样判断。以前学软件，很多时间花在找命令、查参数和处理报错上。现在这些事情可以边做边问，方便了很多，我也更希望把精力放在理解计算本身。

我通常把 Chatbot 和 Agent 分开使用。不懂的概念，可以和 Chatbot 反复讨论；到了实际操作，再让 Agent 查文件、改输入、运行程序。我也会看它怎样找资料、调用了哪些工具，以及到底改了什么。看着它做一遍，再自己检查输入和输出，往往就能慢慢熟悉这套操作。

我更习惯半托管。脑子里先有一个计算计划：手里有什么结构，想比较什么，接下来还缺哪一组结果。比如比较两个结构的能量，先把参考条件和需要固定的参数想清楚，检查一组输入与输出，再让 Agent 批量准备文件、修改参数和整理结果。遇到异常时，回到输出里看看发生了什么，然后再决定下一步。这里的计划，就是自己对计算的打算。

做计算的大部分时间其实是在等程序运行。很多时候改几行输入、提交任务、看一眼输出，让 Agent 帮忙就已经省了不少功夫。软件命令可以在这个过程中慢慢熟悉。对还不太了解的方向，我还是建议先学一下方法，至少能说清楚主要参数的意思，看出结果有没有回答自己的问题，再把任务交给它。

结果靠不靠谱，是我最关心的事情。参数的含义要对照相应版本的官方文档，实际算了什么要看输入和原始输出，数值是否可靠还要做收敛测试与物理检查。和另一个模型聊一遍，有时能发现遗漏；最后作判断时，我仍然会回到这些计算记录上。结果不支持原来的猜想，也值得认真看下去。

Atlas 就沿着这个想法慢慢写。正文保留具体的输入、终端操作、输出和后处理代码，希望读完一个算例，能知道每一步为什么要做，也能看懂软件给出了什么。刚开始接触实际计算，可以从 [Si 的 SCF、能带与 DOS](/Atlas/learn/si/) 读起；已经有具体任务，就从[计算目录](/Atlas/?open=1)找到对应页面，再结合官方文档和自己的体系继续做。
