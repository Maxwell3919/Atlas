最近在想 AI 和 DFT 计算的事情。Atlas 的 README 一直没写，之前是不太想在里面讲废话，毕竟这是一个教学网站。可是又想把一些自己的心得留在这里，一直不知道怎样写出一份信息密度高、又不会太枯燥的文档。

我把 AI 工具大致分成 Chatbot 和 Agent。大家可以经常和 Chatbot 讨论，学习自己还不熟悉的知识。Agent 能直接在电脑上运行，也能远程访问服务器，更适合通过工具操作文件、执行程序。用它做事的时候，也可以看它找了什么资料、用了哪些工具、怎样完成这些操作。

那我们做 DFT 计算，真正需要的是什么？有一个物理概念或物理问题，找到合适的方法去检验，再分析结果，判断自己的猜想是否成立。Agent 能缩短从官网学习软件操作、熟悉计算流程的时间，让我们更快进入实际计算。命令可以一边做一边学，物理问题和计算方法还是要自己理解。

这里想谈的是全托管和半托管，暂时不讨论纯人工。全托管时，你让 AI 沿着给定的 Harness 去试错，一直尝试到得到结果。这个过程可能花很多时间和 token，也会留下大量自己来不及逐一核对的记录。我更推荐半托管：你脑子里先有一个 Plan，再让 Agent 帮你完成其中的操作。这里的 Plan 是自己对计算的打算，与在 Agent 里切换到 Plan 模式是两回事。

在 Agent 响应足够快的前提下，可以让它批量创建输入文件、修改参数、整理结果，减少自己反复操作的繁琐。正式计算时，往往只需要少量修改和命令行交互，剩下的大部分时间都在等程序运行，正好可以继续思考。你知道当前要做什么，也就能在任务偏离需求时及时调整；文档和资料的查询，也可以让它一起帮忙。

当然，如果所有操作都依赖 Agent，而自己失去了辨别能力，那么半托管和全托管也没有多大区别。你可能在这个过程中学到了操作，却不知道学得是否正确。也不必因此焦虑，即使没有 Agent，自己学习软件本来就有大量试错。怎样使用更适合自己，可以在实际计算中慢慢判断。

我们始终需要明确，做 DFT 要了解自己需要的是什么，也要知道正在做什么。LLM 会产生幻觉，所以严谨的工作离不开交叉检验。已经熟悉这个方向的人，半托管可以是一种效率较高的工作方式；如果对相关方法和操作还不太了解，我还是建议先学一下，再使用 Agent 辅助。

这也是 Atlas 存在的意义：让你对分析材料性质的方法有一个初步了解，知道计算怎么完成、结果怎么提取和分析。之后结合 Agent 查阅对应软件的官方文档，明确自己的需求，再提交相关计算。
