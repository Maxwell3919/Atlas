这个 README 一直没写。之前觉得，Atlas 既然是个教学网站，把计算和操作写清楚就好了，不太想往里面放空话。最近一直在想 AI 和 DFT 计算的事情，还是想把一些自己的想法留在这里。

我现在会把 Chatbot 和 Agent 分开来看。不懂的概念，可以拿去和 Chatbot 反复讨论；到了实际操作，Agent 能直接查手册、写输入、运行程序，用起来确实方便。以前学一个软件，常常得在命令、参数和报错里绕很久，现在很多事情可以边做边问。不过，我们自己始终要知道：要算的物理量是什么，为什么需要这一步，得到什么结果才算回答了问题。

我更习惯半托管。脑子里先有一个计算计划，再让 Agent 去做那些重复的事情，比如批量准备输入、修改参数、整理输出。这里说的“计划”，是自己对计算的打算：手里有什么结构，想比较什么，接下来缺哪一组结果。Agent 里的 Plan 模式可以帮忙梳理，但这些问题仍需要自己想清楚。遇到异常时，我也希望能看出它为什么停在这里，再一起决定下一步。

毕竟，做计算的大部分时间是在等程序运行。很多时候改几行输入、提交任务，再看一眼输出就够了，让 Agent 帮忙已经能省掉不少功夫。我会关心它怎样查资料、怎样调用工具，也会看它到底改了什么。软件操作可以慢慢熟悉，判断结果的能力也要在这个过程中积累起来。

这件事最让我在意的还是结果靠不靠谱。DFT 的输入能运行、程序能结束，并不意味着物理问题已经解决。LLM 也可能把软件参数或计算方法理解错。所以我会让它对照官方文档，自己看实际输入和原始输出，再做相应的收敛测试与物理检查。换个模型聊一遍可以带来新的想法；真正拿来判断的，还是计算留下的证据。

Atlas 就沿着这个想法慢慢写下去。希望读完一个算例，能知道自己要算什么，也能看懂软件在做什么。对还不熟悉的方向，先学一下，再把自己的需求说明白，让 Agent 帮忙。如果刚开始接触 DFT，可以从 [Si 的 SCF、能带与 DOS](/Atlas/learn/si/) 读起。输入、输出、后处理代码都放在对应页面里，边看边试。
